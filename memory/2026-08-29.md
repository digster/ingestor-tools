# 2026-08-29 — Rebuild `../newsletters` for full Gmail message IDs

Downstream follow-up to `gmail-ingestor`'s migration to
`{slug}_{full_16_char_message_id}.md` + an `id:` front-matter field.

## Code changes (`src/newsletter_organizer.py`)

- `extract_truncated_id` → `extract_message_id`. Behaviour unchanged (still
  returns whatever follows the last `_`); the name was simply wrong once IDs
  stopped being truncated.
- `find_raw_files()` rewritten: glob-and-prefix-scan → direct existence check on
  `raw_dir / f"{id}.html"` and `.txt`. Was O(raw files) per markdown file
  (~544M path comparisons); a full rebuild now takes ~20s. Added a guard
  rejecting IDs containing path separators — the old scan could only return
  paths inside `raw_dir`, a constructed path cannot.
- Removed two dead imports (`glob`, `os`) — the module used `Path.glob`.
- Local variable and log wording: `truncated_id` → `message_id`.

## Tests: 25 → 32

New: exact-lookup regression using the real `1953e3be…` colliding pair, a
"shared prefix alone matches nothing" case, `.html`-before-`.txt` ordering, path
traversal rejection, an end-to-end split test, and an invariant test that every
output directory holds exactly one `.md`. The integration fixture was pairing
8-char `.md` stems with 16-char raw files and only passed because the old lookup
was a prefix scan; it now uses full IDs throughout.
